## Version control practices

### Version control
- Contains all the source code for your project and maintains the current and historical state of the code.
- Needs to be used by all the teams who touch the software.
### Best Practices
- Always use version control
- Put it all in version control.
- Commit often, commit small features
- Use easy-to-understand commit messages
- Don't commit broken code.
- Consider using a master branch approach
- Developing off trunk or master generally offers better performance
- Branch by Abstraction
  ![Screenshot 2025-05-21 08:22:45](https://github.com/user-attachments/assets/16a22234-1712-46a0-b10c-4e03ad8a5fc6)
- Commit hooks enforce quality
- Commit precommit testing hooks
- **Be careful with secrets**

## Building Artifacts

### Benefits of Artifacts
- Reliability
- Composability
- Security
- Shareability
### Reliability
![Screenshot 2025-05-23 18:31:11](https://github.com/user-attachments/assets/99e9f9ec-0153-4983-bf38-02d5569bcf8d)

### Composability
- Packaging can provide dependancy management between your code and its dependencies and between it and other pieces of software.
- consider wrapping different techonologies in a common packaging format - rpms or debs before deployment to a server
- can also have multiple layers of artifacting
  - **Example** - JARs bundled into **debs**, then use **HashiCorp** packer to create **VMware** images from the **debs**. The VMware images are the artifact that actually is shipped to the customers. For creating debs could use **Maven** with its plugin **jdeb**, same can also be done using **fpm**
### Security
- do not pack sensitive information into packages
- control who has access to packages
- control how code gets pushed to production, by gating who can write to artifact repository
- **Best practice is to only let production deployments come from the artifact repository and only allow the CI system to write to the artifact repository. This way you get a high level of complience, because this way you not allowing someone to sneak code into production without it going through the controller CI process**
- You can also curate external packages to your repo so that when they disappear or change, you have a reproducable build and you don't have deployments fail
### Shareability
- could be shared across members of the team
