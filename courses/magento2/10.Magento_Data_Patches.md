## Data Patches
- those are classes implementing `DataPatchInterface`
- tipically provided as self-suficient modules or in group of ew patches in a module
- could add attributes programatically
- [A good tutorial](https://developer.adobe.com/commerce/php/tutorials/admin/custom-text-field-attribute/#code-reference)
- **Remember to create your patches under `Vendor/Module/Setup/Patch/Data/CustomPatch`**
## Issues
- CASE: You created a module with patch, was able to show the attribute in admin, now you want to change input type of the attribute
    - find in DB table `setup_module` the row of your module and delete it.
    - find in DB table `eav_attribute` the row with your attribute and delete it.
    - find in DB table `patch_list` the row with your patch class and delete it.
    - run `setup:upgrade`, `rm -rf generated/* var/cache/*`, `setup:di:compile`
    - your changes should show now.

- CASE: You are doing something in admin or trying to run console command and magento throws you an error `Exception #0 (ReflectionException): Class does not exist`
    - a possible reason is that an attribute was defined previously with some module, now this module doesn't exist, or name of class defining patch was changed
    - so, go in console and type `grep -rnw -ie "ClassNameFromTheError" generated/` if nothing do the same but this time for dir `var/cache`
    - you'll probably find highlighted in red the name of class you're searching for and somewhere arround it the attribute_code which was defined with it.
    - now do the steps from CASE above to clean those leftovers and you should be fine.
