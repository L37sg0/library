## Version control practices

### Version control
- Contains all the source code for your project and maintains the current and historical state of the code.
- Needs to be used by all the teams who touch the software.
### Best Practices
- Always use version control
- Put it all in version control.
- Commit often, commit small features
- Use easy-to-understand commit messages
- Don't commit broken code.
- Consider using a master branch approach
- Developing off trunk or master generally offers better performance
- Branch by Abstraction
  ![Screenshot 2025-05-21 08:22:45](https://github.com/user-attachments/assets/16a22234-1712-46a0-b10c-4e03ad8a5fc6)
- Commit hooks enforce quality
- Commit precommit testing hooks
- **Be careful with secrets**

## Version Control in Action with Git

### Exercise:
- git clone https://github.com/wickett/word-cloud-generator.git
- git log - to show repository history
- git show <commit-id> - to show details about commit and what was changed
- git status - to see modified files
- git diff - to check what actually was changed
- using hooks:
- ![Screenshot 2025-05-21 08:38:15](https://github.com/user-attachments/assets/03768569-d333-4d1d-9554-afa2a4e3d0b3)
- Hooks are litle scripts which job is to do some testing before commit like logical errors or mistyping. Will prevent you from commiting to the branch.
- linking - just link an issue in your commit message like this "Commit message - #10" - for issue with id 10
- Webhooks - they allow external services to be notified when certain events happen - with a POST request for example
